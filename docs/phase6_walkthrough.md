# 第六阶段：先做 5 条人工标注

> 历史人工操作说明：用户现已选择 AI 代标，无需继续逐条填写。最终交付以 `docs/phase6_final_delivery.md` 为准。

打开本地应用 http://127.0.0.1:8501 ，必要时刷新，左侧选择「人工标注与评估」。

1. 集合保持「开发集 · 200 条」，本次只做编号 001—005。暂不打开独立测试集。
2. 选择评论编号，读原文与标注规则，点击「开始 / 继续计时」。离开页面前点暂停。
3. 填写真实标注者代号。先判断范围，再判断情感；无具体负向问题时标签留空。
4. 选择负向问题标签，并填写证据 JSON。例如下面只说明格式，不能复制成真实答案：

```json
[{"label":"product_quality.color_fading","quote":"从当前原文逐字复制的连续片段"}]
```

5. 保存人工标注。对照原文自行复核后，填写复核者代号，勾选确认并点「确认人工复核通过」。如果由同一个人复核，填写同一代号，不称为双人复核。
6. 换下一条。做完 5 条后告诉我「开发集前 5 条已标注」，我检查格式、计时与歧义记录，再继续后续批次。不要把独立测试正文或答案发到聊天里。

界面只收集人工答案，不展示模型答案。保存修改会撤销该条旧复核状态，记录保存在本地 SQLite；原 CSV 不被覆盖。

## 评估方案

- 先完成 200 条开发集并确定规则，再人工标注、复核固定的 100 条独立测试集。
- 测试答案冻结时记录答案、任务、规则及平台导出的 SHA256；冻结后不能在原测试上继续改答案调参。
- 实际预测须使用冻结版本的已发布 Dify 应用，记录运行 ID、批次、失败和耗时；每批最多 5 条。当前还没有执行 100 条付费测试调用。
- `python scripts/evaluate_heldout.py` 默认只检查准备状态，不调用 API。没有人工真值时返回 pending，不输出伪造指标。
- 情感计算五类固定 Macro-F1、Accuracy；范围计算三类；问题计算固定词表多标签 Micro/Macro-F1、完全匹配率及各标签支持数。
- 全部固定测试 ID 保留在分母。失败项情感与范围计错；问题微平均按标签计数，还要同时报告契约通过率及完全匹配率。零支持类 F1 按 0 处理并明确展示。
- 平衡抽样与小样本结果不能直接外推国内某平台表现。需求摘要不当成分类准确率评分。

## 耗时实验

标注界面的主动计时只是人工标注记录，页面后台停留、未暂停离开会影响记录，应在备注说明。它不能直接证明 AI 提效。

正式效率比较须针对相同固定 300 条、相同交付质量口径，分别记录纯人工流程总时间与 AI 辅助流程的准备、调用等待、失败处理、人工复核修正、汇总时间。重复处理同一批会有熟悉效应，必须披露，并尽可能分组平衡顺序。不要用 API 运行时间除以估算人工时间宣称提升。
